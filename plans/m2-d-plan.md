## 1. Goal

Implement M2-D "queue, attachments and undo in virtual/headless form": authoritative durable follow-up/steer queue with crash-boundary receipts **and reopen replay**, structured attachment snapshots with stale-dispatch refusal, native change groups with quota-accounted preimages, undo eligibility with compensation (never atomic-claimed, never twice-applied), and rewind lineage without filesystem mutation — all through pure state and core/temp-file integration, before any terminal controls.

**In scope**

- Durable queue replay/reconciliation on reopen (reconstruct queue + holds + ack index from `queueAdmitted`/`queueUpdated`; sent-but-uncompleted ⇒ unknown ⇒ hold; durable ack replay so epoch/checkpoint clearing cannot resurrect duplicates): QUEUE-06, STATE-02 (durable half), STATE-03.
- Queue hardening: dispatch-time route/consent re-validation under the new epoch (QUEUE-10 route half); head-barrier hold-instead-of-skip (a held head sets `queueHeld`/head barrier so later entries cannot overtake); validate-before-marking-dispatched (reordered `finishRunWithQueue`); structured headless approval stop that holds the queue (QUEUE-11 transition half — the UX test row is M4, the hold mechanism is M2); cumulative-text budget test (QUEUE-09 byte half; count half already pinned by `queueCapsReject`).

Capture is atomic: read + re-stat/re-hash, refuse or re-capture on change during capture. Stale rule (hash changed or grant gone ⇒ hold + `staleAttachment`, never silent refresh/skip); sealed-vs-tool excerpt/manifest distinction; cancel/withdraw ⇒ zero dispatch; epoch switch before dispatch ⇒ re-consent hold with explicit operator retarget (no silent carryover, no stranding): QUEUE-08, QUEUE-10 (dispatch half), MENTION-09/10/11/12.

## 3. Slices

Each slice is independently implementable, testable, and reviewable (per-slice DeepSeek review). Order is dependency order: D0 → D1 → D2 → D3. D0 defines no attachment types; D1 owns all attachment validation (resolves the REV1 D0/D1 dependency violation).

### D0: durable queue + replay + head barrier (Medium-Large)

Goal: the queue survives reopen with its holds, acks, and unknowns intact, and no head entry can be skipped or overtaken.

- Durable queue replay on reopen: reconstruct queue entries, `.held` states with reasons, and the ack index from `queueAdmitted`/`queueUpdated` records (queued path only — fresh-run direct admissions carry no queue records, so their ack idempotency stays in-memory as today, already tested; no behavior change there, stated honestly). Sent-but-uncompleted work reconstructs as unknown ⇒ hold via the dispatch-linkage rule below. Durable ack replay for queued entries: a retried command ID after epoch change or checkpoint returns the original admission (fixes the `:941`/`:959` clearing hole for the queued path); the `maxAdmittedCommands` prune rule stays replay-consistent (a retry of a pruned ID admits as new — documented, tellable, unchanged).
- Durable dispatch linkage (new, required for QUEUE-06/STATE-03 truthfulness): at dispatch time, BEFORE marking `.dispatched`, commit a link record binding queue entryID + commandID ↔ provider run/request/effect/epoch in the same atomic group. Crash boundaries are exactly: (1) `queueAdmitted` committed, no link (never sent); (2) link + `queueUpdated(.dispatched)` committed, no run completion AND no run failure for the linked runID (sent, outcome unknown ⇒ reconstruct as held-unknown on reopen — never auto-resend, which is STATE-03's "no unsafe automatic resend" by construction); (3a) provider run completed (`completed` event with the run's digest) ⇒ history stands, no hold from this entry; (3b) linked run FAILED (run-keyed `failed` event) ⇒ history stands AND the queue holds exactly as a live failed run holds it, until an explicit resume recorded after the failure (determinate, not unknown); an explicit reconcile (requeue) supersedes an uncompleted link. `.admittedToHistory` is the pre-send history marker (written at dispatch, atomic with `.dispatched`) — it is part of boundary (2), NOT a completion proof; completion/failure is boundary (3) only. Kill at each ⇒ receipts + no duplicate provider input/side effect on reopen+resume (QUEUE-06).
- Head barrier: any held head (attachment, route, approval, unresolved) sets `queueHeld` with the specific reason; later entries cannot overtake while the barrier stands; the barrier clears only by fix, explicit operator remove/withdraw, or retarget-and-reconsent (I-1 enforcement; resolves the overtake hole — marking `.held` alone is not a barrier).
- Validate-before-marking (single pre-marking checkpoint, unambiguous ordering): `finishRunWithQueue` validates route/consent (D0; D1 adds attachment-freshness at the same checkpoint) BEFORE marking `.dispatched` and emitting any receipt; only a passing entry is marked and handed to `admitReservedRun` for dispatch. A refusal never leaves a committed `.dispatched` entry that was never sent, and `admitReservedRun` performs no second validation that could be read as post-marking — the checkpoint is the gate.
- Crash boundaries redefined around actual durable boundaries (the old "queued vs dispatched vs delivered" assumed a delivered state that does not exist): (1) `queueAdmitted` committed, nothing sent; (2) link without run-terminal event, no completion AND no failure for the linked run; (3a) completed (`completed` event keyed by run digest) ⇒ done; (3b) failed (`failed` event keyed by run digest) ⇒ done but queue held until explicit resume. Kill at each ⇒ receipts + no duplicate provider input/side effect on reopen+resume (QUEUE-06); uncompleted-and-unknown ⇒ hold, never resend (STATE-03).
- Dispatch-time route/consent re-validation under the current epoch at that checkpoint (QUEUE-10 route half); refusal holds with reason, never skips. `holdForApproval` holds the queue with a structured reason; zero implicit dispatch on the headless path (QUEUE-11 mechanism; the UX test row is M4).
- Resume retarget path: `resumeQueue` with stale `targetEpochID` entries requires explicit operator retarget (update target + re-consent) — entries never silently carry over and never strand invisibly; stranded entries are listed with their hold reasons.
- Cumulative-text budget test (QUEUE-09 byte half): fill to 64 KiB *including snapshot excerpts once D1 lands* (D0 tests with text only; D1 adds the excerpt-accounting leg — the accounting rule itself is fixed here: excerpts count toward the 64 KiB budget).
- Exit: QUEUE-06/09(both)/10(route); STATE-02(durable)/STATE-03; replay + barrier + retarget tests green at pure/state/temp-file tiers; no M2-A/B/C lane regresses.

## 4. Critical invariants (cross-slice, non-negotiable)

- I-1 (fail-closed dispatch + no overtaking + no loss): no dispatch on stale attachments, missing grants, failed re-validation, missing preimages (fail closed — no explicit non-undoable path in M2-D), or unresolved outcomes. Refusal holds with reason via the head barrier; skipping AND overtaking a held head are both forbidden. Reopen reconstructs the queue, its holds, and its ack index from durable records (I-1 covers replay/no-loss, not just dispatch); sent-but-uncompleted work (link without completion) reconstructs as held-unknown, never auto-resent.
- I-2 (no silent refresh): a snapshot is never refreshed under a queued entry; staleness holds the queue and is operator-visible. Capture itself is atomic (read + re-stat/re-hash or refuse/re-capture).
- I-3 (no second inverse): duplicate or interrupted undo never runs a destructive inverse twice; the write-ahead journal + undo command ID make reconciliation idempotent-safe.
- I-4 (no overwrite of user work): eligibility is governed by current file hash AND after-identity (dev/ino/mode captured at commit — never reconstructed); any divergence refuses with per-file conflicts.
- I-5 (history append-only): undo/rewind create new receipts and notices; earlier tool history is never rewritten (STATE-05).
- I-6 (quiescence, strengthened): undo and dispatch-after-hold run only when there is no in-flight tool, no active provider stream, no unresolved outcome, and no deliveryUnknown; compensation additionally requires the exclusive undoing phase.
- I-7 (exec excluded): shell-produced effects are never ledger-undoable; the disclaimer is a notice, not a flow (settled by spec; not a decision).
- I-8 (boundedness preserved): queue 20-item / 64 KiB-text bounds (excerpts counted), snapshot excerpt caps, and preimage quotas apply on every path including undo and re-admission; refusals are typed, never silent drops.
- I-9 (no terminal in core): all D0–D2 behavior provable via pure state + temp-file integration (+ actor harness in D3); terminal controls are M4 and must not leak into core transitions.
- I-10 (notice visibility/ordering): every undo/partial/exec-disclaimer notice is a defined transcript entry emitted in the same record group BEFORE any subsequent provider request, projected to terminal, JSONL, and export; no hidden prompt additions.

## 7. Design decisions (resolved defaults + genuinely open items)

Resolved in REV2 (defaults fixed; slice reviews verify, not re-decide):

- R-2 Snapshot bytes: hash + identity + excerpt only; no full-byte artifact refs (the read tool fetches content; staleness needs hash+identity, not bytes).
- R-3 Undo scope: file-restore only; exec effects excluded with disclaimer (settled by COMPLETE-SPEC.md ¶924 and UNDO-06; not reopened).
- R-4 Missing preimage: fail closed, always, in M2-D. No explicit non-undoable grant path (UNDO-10's riskier branch ungated by typed headless consent; deferred as a future decision, not built now).
- R-5 Rewind lineage: separate `LineageFork` record, not `parentEpochID` reuse (no M3-C cache-epoch coupling; M3-C composability proven at M3-C planning).
- R-6 Change-group granularity: one group per dispatched mutating batch; partially cancelled/unknown batches contribute only proven-done members.
- R-7 M4 seam: exit check at each slice review (snapshot/notice/record shapes consumable by M4), not a design decision.

Genuinely open (must be decided before the dependent slice; operator/reviewer input required):

Fixed defaults recorded here for confirmation at authorization (not re-decided without cause):
