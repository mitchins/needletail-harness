## 1. Goal

Implement M2-C "execution and permission gates": a model-invoked, operator-authorized native `exec` tool through the production durable agent loop, preserving every M2-A/B guarantee.

**In scope**

- `exec` contract per SPEC §8.5: executable identity, argv array, workspace-relative cwd, timeout, explicit environment overlay; direct argv execution default.
- Authorization architecture: operator flag `--allow-exec`, two-factor grant (operator flag ∩ config), effective-capability intersection unchanged as the authority, per-command approval with resolved-command display bound by content digest.
- HEAD-03 deliberate resolution: validation-before-approval for exec, no validation bypass, regression updates (§3.2).
- Exec identity resolution as a first-class durable step: anchored symlink-resolving resolve → qualify → content-digest → approval binding → spawn re-verification on the held fd (§3.4/§3.4b).
- Process mechanism: extend the existing bounded runner with session/process-group semantics, SIGINT→TERM→KILL escalation, exec-error pipe, identity qualification, env/cwd policy, output bounds, artifact publication (§3.5–§3.6).
- Durable integration: intent-before-spawn, truthful receipts, unknown-outcome holds, ordered-batch composition (`read → edit → exec → read`), cancellation escalation, startup cross-run gate interplay.
- Provider advertisement gating (exec advertised only when granted AND natively composed), epoch discipline.
- Certification: PROC-01…06, POLICY-01/04/06/07 plus the M2-B preservation matrix (§6).

**Out of scope (this milestone)**

- `consult` (remains denied/unadvertised), `diff` advertisement.
- Generic job scheduler, background process manager, recursive agent architecture, bespoke OS sandbox (SPEC §10.4).
- Group-escaped descendant containment and post-escalation persistence (exposed limitations, PROC-04).
- CLI observe-mode selection (§6 re-scope).
- macOS native qualification (Linux-first; `canImport`-portable where free).
- Terminal UI / M2-D / M3 work.

**Certification targets** (catalog `due=M2` unless noted): PROC-01…06, POLICY-01, POLICY-06, POLICY-07, POLICY-04 (due M1 — preservation regression, §6). Preservation: HEAD-03 actor+binary, M1-D demo approvals, TOOL-09 ordered halt, B5C approval/deny legs, CrashMatrix SIGKILL stages, CrossRunGate, STORE-02.

### 3.3 [D3] The `exec` contract: one strict, bounded shape

```json
{
  "executable": "/abs/path/to/exe",
  "argv":        ["/abs/path/to/exe", "a", "b"],
  "cwd":         "sub/dir",              // OPTIONAL — omitted ⇒ workspace root (the only way to name the root, since validatePath rejects "." and empty)
  "timeoutSecs": 120,
  "env":         {"K": "v"}
}
```

- `executable`: absolute, byte-exact components ≤ 4096 B total, **component rules identical to `validatePath`** — empty, `.`, `..`, and trailing-slash components rejected, **each component ≤ 255 B** (REV8; a longer component would otherwise fail late in the walk as `.notFound` instead of `invalid-arguments`), no NUL, **no PATH search** (SPEC §8.5).
- `argv`: 1…64 entries, each ≤ 4096 B, NUL-free, printable-safe; `argv[0]` == `executable`; batch ≤ 512 KiB; **≤ 8 exec proposals per batch** (NC-15).
- `cwd`: workspace-relative `validatePath` string rules (`ToolValidator.swift:389-416`) — **shape only**; existence/identity bound in the resolution phase.
- `timeoutSecs`: strict integer (booleans/strings rejected), `[1, 1800]`; effective = `min(requested, deadlines.exec, dispatch ceiling)`.
- `env` overlay: 0…32 keys, `[A-Za-z_][A-Za-z0-9_]*` ≤ 256 B, values ≤ 8 KiB NUL-free printable. **NC-10 (ADR): approve-and-display denylist** — fixed deny-set refused at validation AND re-checked at spawn merge (`PATH`, `LD_*`, `DYLD_*`, `IFS`, `ENV`, `BASH_ENV`, `BASH_FUNC_*`, `SHELLOPTS`, `PS4`, `GCONV_PATH`, `GLIBC_TUNABLES`, `PERL5*`, `PYTHON*`, `RUBYOPT`, `RUBYLIB`, `NODE_OPTIONS`, `NODE_PATH`, `JAVA_TOOL_OPTIONS`, `GIT_CONFIG_GLOBAL`, `GIT_EXEC_PATH`, `GIT_SSH_COMMAND`, `SSH_AUTH_SOCK`, `SSH_ASKPASS`, `SSL_CERT_FILE`, `LOCPATH`, `NEEDLETAIL_*`), plus the **credential-name register** applied at the **reducer/authoriser layer** (the validator stays pure): the epoch's config snapshot carries `profiles[*].credential` names; the reducer rejects overlay keys in that derived set with a typed `invalid-arguments` receipt. Base env fixed-minimal, never inherited — credential absence is structural; every overlay byte is displayed and approved per command. Residual (`PAGER`, `EDITOR`, `HOME`, `TMPDIR`, `USER`…): approvable-by-display, in the ADR.
- Display bound (m12): rendering caps at 8 KiB/call with explicit omission markers; overflow ⇒ `invalid-arguments`. `Sources/NeedletailRuntime/TerminalApprovalGateway.swift` gains bounded rendering.
- Result mapping: `status` ∈ `success`/`failed`/`timeout`/`cancelled`/`conflict`/`invalid-arguments`/`denied`. **Status taxonomy for resolution failures (REV5):** `.notFound/.qualification/.cwd/.budgetExceeded` → `invalid-arguments` (the request as shaped cannot be served); **`.unavailable` → `failed`** with summary `resolution unavailable` — an infrastructure refusal is not an identity-binding verdict (`conflict` is reserved for digest/cwd mismatches), and `failed` is in the deterministic set; justification recorded in NC-16.
- Shell/interpreter honesty per SPEC §10.4; literal argv in the display.

### 3.4 [D4] Exec identity: anchored symlink-resolving resolve → qualify → content-digest → bind → re-verify on the held fd

- **Anchored resolution with symlink following (REV5/REV6/REV7):** per-component anchored walk from `/` using `openat(O_DIRECTORY)` for directories; each entry is probed with `fstatat(AT_SYMLINK_NOFOLLOW)` (or `O_PATH|O_NOFOLLOW` + `fstat`) so a symlink is **detected before any ELOOP**, resolved with `readlinkat` — target absolute ⇒ restart the walk from `/`; relative ⇒ continue from the current directory fd — with **≤ 40 hops and ≤ 4096 B cumulative target length**, else typed `.qualification` failure. The hop budget applies to final-component symlinks too: they are resolved like any other, and the walk continues until the resolved final opens as a **regular file** (checked by `fstat` on the opened fd; a non-file final ⇒ `.qualification`). **Canonical stack (REV7):** the display path is the normalized resolved stack — absolute-target restart resets the stack to `/` + target components; relative targets append with **openat-plus-stack-pop for `..` components inside symlink targets** (a symlink target like `../lib/x` pops the last stack element and continues from the parent fd — an pop past the root anchor ⇒ `.qualification` failure); the *requested* path cannot contain `.`/`..` (validator rules, §3.3), so the stack starts clean. The exec re-obtains this identity at spawn: **phase 1 returns identities only (no FD crosses actor hops); the spawn re-runs the anchored walk to obtain the fd it hashes and execs** — only the final `execve` is fd-based, and the digest match binds phase-1 and spawn identities. `argv[0]` = the fully resolved path (matching the display; the requested path remains visible in the approval's requested field).
- **Qualification:** regular file, exec bit, no group/world-write, owner root-or-current-user (the `qualifiedRgFD` checks, applied to the resolved final component).
- **Content digest:** sha256 over the held fd's bytes (> 64 MiB rejected — hash cap, independent of the 32 MiB storage caps) + `dev/ino/size`. At spawn, the executor re-runs the anchored walk, re-qualifies, re-hashes, and requires equality with `approvedExecDigests[callID]`; **absent or mismatching ⇒ typed `conflict`, epoch-independent** (third hard gate). Residuals documented: nanosecond in-place write between re-hash and `execve` (same-inode race only; memfd/fexecve future hardening); script/interpreter content reached at run time is not digest-bound.
- **cwd identity (REV7/REV8 containment):** the cwd walk is **anchored at the pinned workspace root fd** (cwd is workspace-relative by schema); relative symlink targets continue within; **a relative target popping past the workspace root (stack-pop below the anchor) fails typed `.cwd`**; an absolute symlink target is re-anchored at `/` and must **re-enter the workspace-root prefix** (dev/ino comparison against the pinned root along the resolved stack) or the resolution fails typed `.cwd` — containment by construction. The cwd walk inherits the hop (≤ 40) and target-length (≤ 4096 B) bounds; `.` and empty components inside targets are skipped during normalization. Read roots are never exec cwds. dev/ino of the resolved cwd is bound in the resolution phase; spawn re-open + compare; mismatch ⇒ `conflict`. No FD crosses actor hops.
- **Environment:** base fixed-minimal + approved overlay (§3.3). Wrapper scripts for rich-env commands (NC-8). PROC-06: absolute Conda env binary, no activate/install.
- **WorkspaceLock:** held across the mutating batch, bounded by the **batch aggregate** (≤ 8 × per-call dispatch ceiling — REV8: the run deadline is tick-only and does not bound this; an aggregate dispatch cap is a recorded future option, §12); `LOCK_NB` failure fails typed pre-spawn (R15).

### 3.5 [D5] Process mechanism: extend `runBounded`; do not adopt Subprocess for v0.1

**Decision (NC-3):** session semantics + three-stage escalation + exec-error pipe + argv0 split on the existing runner; `ExecRunner` composes; `swift-subprocess` stays test-only.

- **Change 1 — session/process group:** child `setsid()` pre-execve (async-signal-safe; exists on Darwin; `#if`-guarded anyway).
- **Change 2 — three-stage escalation (NC-13, REV7–REV10 gating):** deadline/cancel → SIGINT → 2 s → SIGTERM → 2 s → SIGKILL → hard stop +6 s (SPEC §8.5 verbatim). **Split escalation predicate (REV8–REV10):** at every stage, **`kill(pid, sig)` iff the leader has not exited** (`childDone == false`, set from the `waitid` probe), and **`kill(-pgid, sig)` iff the leader has not been REAPED** (`reaped == false` — a flag set **only** by the final bounded reap, REV10). The group gate keys on **reaped**, not exited: while the leader is an unreaped zombie its pgid cannot be recycled, so group signalling remains safe even after `childDone` — this covers the exact combination an exited-keyed gate misses (leader exits early; a same-group descendant closes its own stdio; both pipes reach EOF ⇒ an exited-keyed gate sends nothing while the group is still alive and signallable). **Post-completion group probe (REV11/REV12, closes the clean-completion bypass):** the baseline drain loop breaks on `childDone ∧ outEOF ∧ errEOF` and skips escalation entirely (`NativeToolExecutor.swift:773, :804, :806`) — under that break the REV9-failing combination would survive under ANY gate key, because no stage is ever consulted. Therefore **on the exec arm only, before the final reap on every return path, the runner enumerates the process group's live members (a bounded `/proc/<pid>/stat` scan matching the pgid — parsing field 5 after the final `)` of comm, or `/proc/<pid>/status`; **"live" = state not `Z` for any member**, so non-leader zombies never trigger the cycle; a numeric scan bound caps entries/time; **enumeration errors — hidepid/EACCES/ENOENT — conservatively escalate with a containment-limitation record** rather than reporting "no members"; non-Linux builds skip the probe and mark exec lifecycle qualification unqualified rather than reintroducing `kill(-pgid, 0)`; on timeout/cancel paths the live leader is excluded from the member count (its own escalation already covers it); excluding the leader's own zombie pid — REV12: `kill(-pgid, 0)` is a group-existence test, not a liveness test, and the deliberately unreaped zombie leader makes it succeed on every clean completion, which would have fired a pointless escalation cycle on every rg/git run; hence the exec-only scope and the real enumeration). If a live non-leader member exists, the full escalation stages (INT → TERM → KILL, standard bounded deadlines) run against the group — a clean-completion run with a lingering same-group descendant is bounded; a genuinely finished exec costs one `/proc` scan (exec completions are per-command, not per-read — the cost budget is stated in R18). An `EPERM` from any signal or probe is treated conservatively as "group exists" and recorded as a containment limitation (a credential-changing descendant, e.g. setuid, is not killed by our signals — documented; setgid/setuid executables remain grantable, SPEC §10.4's allowlist-is-not-containment applies). The rg/git callers keep the baseline completion behavior — their single-process residual is the pre-existing documented limit and their certified matrix is unchanged. Only after the stages (or a member-free enumeration) does the bounded reap sequence run and set `reaped`. After `reaped`, no group signals are sent — the escalation/reap epoch is over (the pgid remains reserved by any surviving members; stopping signals then is the safe direction, and those survivors are the PROC-04-class residue if they also escaped the group). **Post-reap in-group fork race (REV12, documented residue):** a descendant forked between the last group signal and the final reap can survive in-group — a narrow window; documented like PROC-04, not claimed away. Residual escape: a descendant that **left the process group** — PROC-04's limit; these are the only exposed persistence classes.
- **Change 3 — pre-reap ordering (REV4–REV10):** through all stages, child liveness is probed **without reaping** — `waitid(child, WEXITED|WNOWAIT|WNOHANG)` on Linux; the `kill(child, 0)` fallback is stated as **NOT an exit probe** (a zombie answers; it proves existence only) and **Darwin is unqualified for lifecycle certification** (`#if` guard; Linux `waitid` is the certified path). There is **exactly one bounded reap sequence before every return path, clean exit included**: a bounded WNOHANG retry loop (20 × 100 ms, the baseline cancel-path bound, `:819-861`, EINTR-retried) — a still-unreaped survivor is returned with `timedOut` (the baseline's own behavior, `:874, :877`); no blocking reap ever; **`reaped` is set only when this sequence succeeds**, and it is the sole gate for stopping group signals. **ECHILD edge (REV11/REV12):** if the leader was reaped elsewhere (`waitid`/`waitpid` ECHILD — not expected in the single-threaded parent, but safety-critical), an explicit **`unsafeToSignal` flag is set (distinct from `reaped`)**: the probe and **both** pid and group signals are suppressed (recycled-pgid safety) and the run is reported `timedOut` — `reaped == false` alone never re-enables signalling in that state. **Fault-injection seams (REV12):** ECHILD and EPERM are injectable test conditions (probe/signals suppressed; conservative escalate + containment record respectively). C1 distinguishes a systematic unreaped-child leak (stop condition) from the single accepted bounded survivor (`timedOut`). The same discipline replaces the cancel escalation (`:806-866`). C1 distinguishes a systematic unreaped-child leak (stop condition) from the single accepted bounded survivor (`timedOut`).
- **Change 4 — exec-error pipe (NC-11, REV6–REV8):** close-on-exec pipe (spawn-lock protected; lock released at fork return; read deadline-bounded inside the monotonic window; **the parent closes its marker write end immediately after fork** so child-side write failures surface as EPIPE instead of silent success). Framing: child writes **0x01** after `setsid`, immediately before `execve` — **the write is checked: `if write(...) != 1 { _exit(127) }` with EINTR retried** (an unchecked EINTR/EPIPE would let a command that ran be misclassified pre-dispatch — the forbidden direction); on `setsid`/`fchdir`/`dup2`/`execve` failure the child writes **0x02 + 4-byte errno** then `_exit(127)`. **Success predicate: `0x01` seen AND pipe EOF without `0x02`**; **EOF without `0x01` ⇒ typed pre-dispatch failure "child died before exec"** — sound because `0x01` is the last pre-exec write, so its absence proves `execve` never ran. A death in the window after `0x01` but before `execve` is conservatively classified started (claims more effect than real — the safe direction). Real exit-127 ⇒ `failed` + started. Harness crash after fork ⇒ the child is an orphan in its own session, bounded only by its own behavior — PROC-04-class exposed limit.
- **Change 5 — argv0/execPath split (REV8/REV9 fd note):** `runBounded(execPath: String? = nil)`; exec uses `execPath = /proc/self/fd/N`, `args[0] = resolvedPath`. **The qualified fd is deliberately inheritable (CLOEXEC cleared — the rg precedent, `NativeToolExecutor.swift:483-494`) and lifted above stdio via `F_DUPFD` (the same precedent), so the `dup2` wiring cannot clobber `/proc/self/fd/N`** — shebang interpreters and NC-8 wrapper scripts can reopen `/proc/self/fd/N` after exec; the accepted cost is the fd leaking into the child. Display note: for a shebang script the interpreter's argv is `[interpreter, /proc/self/fd/N, …]` and `$0` differs — "display == executed" is exact for the argv vector and the executed image, softened for `$0` (documented, not claimed away).
- **Timeout plumbing (M5):** `ToolDeadlines.exec: TimeInterval = 120` (defaulted init); dispatch ceiling ≤ 1800 s ∧ ≤ remaining run deadline. Tick scheduling out of scope.
- **PROC-04 limit:** group-escaped descendants are outside the guarantee; tests clean up by recorded PID; no false isolation claims (SPEC §8.5/§15).
- Doc drift `:510` fixed; `GitDiff.swift:79-91` re-certified in C1.

### 3.6 [D6] Output: spill lease → staged artifacts with bounded tail and honest omission

- **Drain:** the existing concurrent `poll()` loop (PROC-01 guarantees unchanged).
- **Spill lease (REV5–REV9, resolves Majors ii/iii and the REV8 two-stream Blocker):** new store API pair with default implementations via extension (six test doubles untouched):

### 3.7 [D7] Durability mapping — nothing new to invent, everything to keep

- **Intent-before-spawn:** `dispatchTrustedBatch` commits intents with the dispatch group before the effect.
- **Completion-before-continuation:** per-call outcomes → `continueAfterEffectPerCall`; continuation only after the result group commits.
- **Unknown post-dispatch ⇒ hold:** crash after spawn before receipt ⇒ `outcome_unknown` ⇒ holds + `CrossRunGate` exit 3 until explicit acknowledgment. **Never automatic retry** (§9.1). POLICY-07 certifies.
- **Proven pre-dispatch ⇒ no false unknown:** schema, resolution failure (batch-wide intent+result receipts), spawn digest/cwd mismatch ⇒ `conflict`, qualification/cwd-open failure, lease-grant/boot-id failure, exec-error pipe ⇒ typed pre-dispatch. A started command's exit is `failed`, never pre-dispatch. **Hold accuracy:** holds arise from the turn-limit precheck, the store-failure edge, and genuinely unknown post-dispatch states — never from the success-path reduction.
- **Ordered batch:** failing exec halts; earlier successes stand; later members `cancelled`+`started:false`.
- **Timeout/cancel:** started ⇒ unknown+hold for mutating (actor fallback `started: true`). PROC-03: runner-level cycles + bounded actor-level cycles (64-marker bound = documented stop).
- **No transaction across execution:** synchronous store APIs; executor runs between store calls; lease/publish are fenced transactions before references exist.

## 9. Cross-cutting rules

- Strict shape-first validator; executor re-validates atomically; capability at authoriser AND exec arm; composition gated at epoch ∧ `hasExec` ∧ spawn-time digest presence (epoch-independent); credential register applied reducer-side.
- Fail-closed: absent config = denied; deny-set env = rejected; identity/content/cwd mismatch or absent digest = conflict; resolution failure = typed batch-wide pre-dispatch (intent+result, reopen-safe; `.unavailable` ⇒ `failed`); lost completion = unknown+hold.
- Test vocabulary: `PROC_n_`/`POLICY_n_`; deterministic barriers; serialized process suites; hermetic child env; cleanup only test-owned PIDs/pgids.
- Receipts list RED probes; probes never deleted; catalog-tier deviations recorded in receipt AND catalog reconciliation.
- No live model endpoints; no package additions (NC-3).

## 10. Explicit non-goals / forbidden

No `consult`/`diff` enablement; no background/detached process feature; no scheduler/agent recursion; no bespoke sandbox; no PATH search; no env inheritance; no automatic retry; no mid-run reconcile; no `--trusted` semantics change (fixture shapes migrate; outcomes preserved); no CLI observe-mode selection; no run-path `--tools` mask wiring; no dependency additions; no macOS qualification claims; no merges without authorization.
